# Architecture

How the skill is organized and what runs when.

## Two layers: skill (global) and project workspace (per-video)

```
~/.claude/skills/short-form-vibe-edit/        ← shared, never modified per-video
├── SKILL.md
├── motion-library/                            ← reusable b-roll components
├── templates/                                 ← blueprints copied per project
├── scripts/                                   ← orchestration logic
├── presets/                                   ← brand themes
└── docs/

~/Desktop/foo-vibe-edit/                       ← created per video, owned by that video
├── project.json                               ← metadata, preset choice, source path
├── public/source.mp4                          ← transcoded source
├── audio.json                                 ← whisper output
├── captions.json                              ← derived caption[] for @remotion/captions
├── scenes.json                                ← source of truth: timings + motion choices
├── scenes.resolved.json                       ← generated by render.mjs from scenes.json
├── src/
│   ├── index.tsx
│   ├── Root.tsx                               ← templated from skill
│   ├── Vertical.tsx                           ← templated, contains brand palette constants
│   ├── broll-registry.tsx                     ← AUTOGENERATED at render time
│   ├── .broll-library/                        ← AUTOGENERATED mirror of skill's motion-library
│   └── broll-custom/                          ← bespoke motion graphics for THIS video
└── out/<projectName>.mp4
```

## Pipeline

```
USER: invokes skill on a source video
    ↓
1. setup-project.mjs
   - validates source exists
   - probes duration via ffprobe
   - creates workspace dir
   - copies templates with {{placeholder}} substitution
   - npm install (Remotion + deps)
   - writes project.json
    ↓
2. transcribe.mjs
   - ffmpeg transcode source → public/source.mp4 (locked recipe)
   - extract audio → audio.wav
   - whisper → audio.json (with word_timestamps)
    ↓
3. plan-scenes.mjs
   - reads audio.json
   - splits duration into 12 alternating B/S scenes
   - snaps boundaries to word ends
   - writes scenes.json (motion=null on b-roll scenes)
   - writes captions.json (word-level Caption[])
    ↓
4. AGENT (Claude) reads scenes.json + motion-library/catalog.json
   - for each broll scene:
     • read scene.words
     • match to library template, set scene.motion = "Timeline" (etc.)
     • OR write src/broll-custom/SceneNN_X.tsx + set scene.motion = "custom:SceneNN_X"
    ↓
5. render.mjs
   - validates every broll scene has a motion picked
   - mirrors motion-library/ → src/.broll-library/
   - generates src/broll-registry.tsx (library + customs)
   - writes scenes.resolved.json
   - npx remotion render → out/<name>.mp4
   - copies to ~/Desktop/<name>.mp4
```

## Why mirror motion-library into the workspace

Remotion's webpack bundles only files inside the project directory. To make library components available without symlinks (which break on some setups), `render.mjs` copies the library into `src/.broll-library/` at render time. The dot-prefix keeps it out of typical glob patterns and signals it's auto-managed.

This means:
- Skill is the source of truth for motion library
- Each render pulls a fresh copy
- Updates to the skill propagate to the next render of any project
- No project ever modifies the skill's library directly

## Why keep customs project-local

A bespoke "Scene07_OurStartupRoadmap" makes sense for one specific video. Promoting it into the global library would dilute the catalog (every video would see it as a candidate even when irrelevant).

If a custom template proves reusable across multiple videos, the user can manually copy it into `motion-library/` + register in `index.tsx` + add catalog entry. That's a deliberate curation step, not automatic.

## Why not use a skill subagent for the motion picking step

The agent (Claude) reading scenes.json and picking templates IS the loop already. Spawning a subagent would just add a layer without buying anything — the matching needs context (the transcript words + the catalog), and Claude already has both in scope while orchestrating the skill.

## Idempotency

- Re-running `setup-project.mjs` overwrites everything (use a different `--workspace` to keep multiple).
- Re-running `transcribe.mjs` re-transcodes + re-transcribes (deterministic — same input → same audio.json).
- Re-running `plan-scenes.mjs` regenerates scenes.json. **WARNING: overwrites motion choices.** If you've already filled in motion fields, don't re-run.
- Re-running `render.mjs` is safe and fast (bundle is cached after first render).
